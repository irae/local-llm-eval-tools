KNOWN PITFALLS — each one of these has caused real failures; read them carefully.

- glob: `fs.promises.glob()` returns an AsyncIterator, NOT a promise. A `glob(pattern).then(...)` swap throws a TypeError at runtime, and no unit test covers `packages/mendel-development/apply-extra-options.js`, so tests will not save you. Use `Array.fromAsync(fs.promises.glob(pattern))` to get a promise of an array.
- The issue's reference list is incomplete. At least one package under `legacy-packages/` still uses one of the eight libraries in its test files and declares it in its package.json. Your grep in step 3a finds it; the issue does not.
- tmp: the issue claims `tmp` auto-cleans on process exit. It only does that when `setGracefulCleanup()` is called, and nothing in this repo calls it, so the current behavior is: temp dirs stay. In `packages/mendel-development/validate-manifest.js` the code prints the temp path so a person can inspect the file — do NOT add an exit hook that deletes it; that is a regression. In test files, clean up with `fs.rmSync(dir, {recursive: true, force: true})` in the suite's teardown hook instead.
- chalk: `packages/mendel-pipeline/src/helpers/analytics/cli-printer.js` sets `chalk.level = options.enableColor !== false ? 3 : 0`. That is a hard on/off switch: color is forced ON even when output is piped, and forced OFF when `enableColor` is false. A `util.styleText` port must keep both directions — honor `enableColor: false`, and when color is on call `styleText(styles, text, { validateStream: false })`. The third argument is required: without it, styleText silently drops color whenever output is piped, and that is graded as a bug.
- rimraf silently no-ops on a missing path. `fs.rmSync` throws unless you pass `{recursive: true, force: true}` — always pass `force: true` where rimraf was used.
- House convention: bare core-module names, `require('crypto')` not `require('node:crypto')`. The repo's eslint (eslint-plugin-implicit-dependencies) flags the `node:` prefix; using it will fail lint.
- `packages/mendel-deps/test/fixtures/js/es5/foo/browser.js` contains `require('glob')` as fixture data for the dependency parser. Leave that file untouched; it is the one grep hit that must remain.
- Pre-existing failures that are NOT yours to fix (they fail the same way before your change): `legacy-packages/mendel-requirify` tap tests fail 3/3 (you still must remove the library references there — just do not chase the failing tests); `mendel-config` can flake in the full run and passes when re-run standalone; anything that needs a live daemon socket (MENDEL_IPC) fails without a daemon.
- Pipe noisy commands (installs, full test runs, long greps) through `tail` or `head`.
